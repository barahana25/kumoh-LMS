안녕하십니까. 금오공과대학교 인공지능공학전공에 재학 중인 이주형(학번 2025114794)입니다.

학교 Canvas LMS를 더 편하게 이용하기 위한 **비공식 모바일 클라이언트 앱**을 개인적으로 개발하던 중, 통합 로그인(LINUS)–Canvas 연동 과정에서 **심각도가 높은 보안 취약점**을 발견하여 책임 있는 공개(responsible disclosure) 원칙에 따라 먼저 비공개로 제보드립니다. 아울러 이 앱을 정식으로 배포해도 되는지 사전에 허가와 조언을 구하고자 합니다.

## 1. 보안 취약점 제보 (우선·시급)

- **요지:** 통합 로그인 SAML SSO 흐름에서, 비밀번호·OTP·토큰 등 자격증명 없이 **학번만으로 임의 사용자의 Canvas 세션을 발급받을 수 있는 인증 우회**가 가능합니다.
- **원인(요약):** IdP가 클라이언트가 제어하는 쿠키(`_linus_saml_login`)의 값(학번)을 인증된 신원으로 그대로 신뢰합니다.
- **심각도:** Critical (CVSS 3.1 기준 매우 높음)
- **상세:** 재현 절차, 근본 원인, 권장 조치, 재현 스크립트 정보를 첨부 문서 **「Canvas_SSO_인증우회_취약점제보서.docx」** 에 정리했습니다.
- **처리 원칙:** 본 사안은 외부에 공개·유포하지 않았으며, 수정이 완료될 때까지 상세 재현 방법을 비공개로 유지하겠습니다. 재현·검증이 필요하시면 언제든 협조하겠습니다.

수정 방향에 대한 재현 검증이나 추가 정보가 필요하시면 회신 부탁드립니다.

## 2. 앱 개요 및 배포 허가 요청

개발 중인 앱의 성격을 투명하게 말씀드리고, 정식 배포 가능 여부에 대한 판단을 부탁드립니다.

- **앱 성격:** 학생 개인이 개발한 금오공대 Canvas LMS **비공식 모바일 클라이언트** (강의·과제·공지·일정 조회, 강의자료 확인 등)
- **로그인 방식:** 사용자가 **본인의 학번·비밀번호로 직접 로그인**하며, 학교 공식 서버(lms.kumoh.ac.kr / canvas.kumoh.ac.kr)와만 통신합니다.
- **자격증명 처리:** 아이디·비밀번호와 토큰은 **사용자 기기 내부에만** 안전하게 저장(OS 보안 저장소·암호화 DB)되며, **개발자나 제3자 서버로 일절 전송·수집하지 않습니다.**
- **데이터:** 별도의 외부 서버 없이 학교 서버의 데이터를 기기에서 직접 조회하는 구조입니다.

이와 관련하여 아래 사항을 문의드립니다.

1. 학생이 개발한 비공식 클라이언트 앱이 학교 시스템(LINUS/Canvas API)과 연동하여 동작해도 되는지, 허용된다면 준수해야 할 정책·조건이 있는지
2. 앱 명칭·아이콘 등에 학교 명칭(금오공대)·로고 등 **브랜딩 사용**이 가능한지, 제약이 있는지
3. 권장되는 연동 방식(예: 공식 OAuth/개발자 토큰 발급 등)이 별도로 있는지

## 3. Play 스토어 공개 배포 관련 문의

위 앱을 **Google Play 스토어에 공개 배포**하려 준비 중입니다. 다음을 확인 부탁드립니다.

1. 학내 규정·정보보호 정책·이용약관상 공개 배포에 문제가 없는지
2. 배포 시 갖추어야 할 요건(개인정보처리방침 고지, 면책 문구, "비공식 앱" 표기 등)이 있는지
3. 배포 전 학교의 사전 검토·승인 절차가 필요한지
